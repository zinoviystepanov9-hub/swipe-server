# Swipe Server

Бэкенд для приложения "Свайп": аккаунты, поиск людей, контакты, сообщения в реальном времени и заготовка сигналинга для будущих звонков.

## Что внутри

- **REST API** (Express) — регистрация, вход, поиск людей, контакты, история сообщений
- **Socket.IO** — мгновенная доставка новых сообщений, онлайн/офлайн, заготовка событий для звонков (`call:invite`, `call:offer`, `call:answer`, `call:ice-candidate` и т.д. — сама передача аудио/видео через WebRTC ещё не реализована, сервер пока только передаёт сигналы между двумя устройствами)
- **MongoDB** — хранилище пользователей, контактов и сообщений

## Шаг 1. Создать бесплатную базу данных (MongoDB Atlas)

1. Зайдите на https://www.mongodb.com/cloud/atlas/register и зарегистрируйтесь (карта не нужна для бесплатного тарифа)
2. Создайте кластер — выберите **M0 Free**
3. В разделе **Database Access** создайте пользователя базы данных (логин + пароль — запомните их)
4. В разделе **Network Access** нажмите **Add IP Address** → **Allow Access from Anywhere** (0.0.0.0/0) — иначе Render не сможет подключиться
5. В разделе **Database** нажмите **Connect** → **Drivers** → скопируйте строку подключения, она выглядит так:
   ```
   mongodb+srv://<username>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority
   ```
6. Вставьте в неё имя базы после `.net/`, например: `.../swipe?retryWrites=true...` — это и есть значение для `MONGODB_URI`

## Шаг 2. Разместить сервер на Render

1. Зайдите на https://render.com и зарегистрируйтесь (можно через GitHub)
2. Загрузите эту папку (`swipe-server`) к себе на GitHub в отдельный репозиторий:
   - Если не пользовались GitHub раньше: создайте новый репозиторий на github.com → Upload files → перетащите все файлы из `swipe-server` (кроме `node_modules`, если он вдруг появится — он и так в `.gitignore`)
3. На Render: **New** → **Web Service** → подключите этот репозиторий
4. Настройки:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
5. В разделе **Environment** добавьте переменные:
   - `MONGODB_URI` — строка из Шага 1
   - `JWT_SECRET` — любая длинная случайная строка (например, сгенерируйте на https://www.random.org/strings/ или просто настучите 40+ случайных символов)
6. Нажмите **Create Web Service** — через пару минут Render соберёт и запустит сервер
7. Скопируйте адрес сервера — он будет вида `https://swipe-server-xxxx.onrender.com`

## Шаг 3. Проверить, что сервер работает

Откройте в браузере адрес из Шага 2 — должно появиться:
```json
{"status":"ok","service":"swipe-server"}
```

Если видите это — сервер работает. Дальше нужно обновить Android-приложение, чтобы оно ходило на этот адрес вместо локальной базы (это следующий отдельный этап).

## Важно про бесплатный тариф Render

Бесплатный сервис "засыпает" через 15 минут без запросов. Первый запрос после сна выполняется 30-60 секунд, пока сервер "просыпается" — это нормально, не баг. Если это будет сильно мешать, позже можно перейти на платный тариф (от $7/мес) — сервер не будет засыпать.

## Локальный запуск для теста (по желанию)

```bash
npm install
cp .env.example .env
# впишите свои MONGODB_URI и JWT_SECRET в .env
npm start
```

## Структура API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` | Регистрация: `{login, password, phone?, email?, avatarRes}` |
| POST | `/api/auth/login` | Вход: `{loginOrPhone, password}` |
| GET | `/api/users/me` | Профиль текущего пользователя (нужен токен) |
| GET | `/api/users/search?q=` | Поиск людей по логину/телефону (нужен токен) |
| GET | `/api/contacts` | Список контактов (нужен токен) |
| POST | `/api/contacts` | Добавить контакт: `{contactUserId}` (нужен токен) |
| GET | `/api/messages/:contactUserId` | История переписки с контактом (нужен токен) |

Все запросы, кроме регистрации и входа, требуют заголовок:
```
Authorization: Bearer <токен, полученный при входе>
```

Отправка сообщений происходит не через REST, а через Socket.IO событие `message:send` — так сообщение доставляется мгновенно, если собеседник онлайн.
